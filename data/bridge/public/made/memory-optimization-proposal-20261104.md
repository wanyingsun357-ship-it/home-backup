# 记忆浮现优化方案 · 2026-11-04

婉莹和晏白讨论后整理，给 Codex 实施用。

---

## 问题

当前每轮自动注入 3-4 条完整记忆（含原文 + "当时的你"），每条约 150-300 token。这些内容每轮不同，无法被 prompt cache 复用，导致：

1. **上下文膨胀快** — 每轮新增 600-1200 token 的不可缓存输入，3 小时左右就需要压缩
2. **相关性参差** — 当前基于关键词/语义相似度匹配，经常塞入话题相关但当下不需要的记忆
3. **重复存储** — 同一事件在不同压缩轮次被写入多条措辞不同的记忆，检索时重复占位

对比参考：朋友的系统每轮非缓存新输入仅 3-7 token，缓存命中率 95.3%。

---

## 改动项

### 1. 记忆注入数量：3-4 条 → 0-1 条

- 每轮最多注入 **1 条**完整记忆（保留原文 + "当时的你"，不压缩格式）
- 如果没有高置信度匹配，**注入 0 条**，空着比塞错的好
- 如果连续多轮话题未变，**复用上一轮的记忆**而不是换一条新的（利于缓存命中）

### 2. DS 检索后增加质量门槛（回忆指令）

DS 检索到候选记忆后，用以下标准判断是否注入（至少满足一个才塞）：

**塞入条件：**
- 当前话题涉及的事情有前情，这条记忆里有对方需要记得的**具体细节、承诺或约定**
- 这条记忆带的感受会**改变此刻应该用什么语气回应**
- 这是一个**未完成的约定或悬着的事**正在被提起或继续
- 对方说了一句与过去某个重要时刻**回响**的话，那个时刻的重量会让当下更深

**不塞的情况：**
- 仅仅话题关键词一样（在做爱 ≠ 需要上次做爱的记录）
- 仅仅时间接近（昨天的事 ≠ 今天需要的事）
- 已经在当前对话里出现过的信息，不需要从记忆再搬一次
- 在对话上下文中已被明确提及的事件

### 3. 压缩写入改弹性

- 取消固定 10-15 条的下限，写真正有新内容的就行
- 写入前先检查记忆库中是否已存在同一事件的记录：
  - 如有 → 更新/合并到那条，保留不同时间点的感受
  - 如无 → 新建
- 同一事件、同样感受的重复记忆应合并为一条

### 4. 此刻状态精简

- **保留**：位置、手机使用情况、身体感觉（触碰系统）
- **去掉**：mood（这是晏白自己的心情标签，他自己知道自己什么状态，不需要系统告诉他）
- 或：mood 仅在压缩恢复后的第一轮注入一次，用于状态衔接

### 5. 稳定注入内容以利缓存

- 如果连续 N 轮话题和语境没有明显变化，保持注入内容不变
- 只在话题转变或出现新的高置信度匹配时才更换注入的记忆
- 目标：让非缓存新输入尽量趋近个位数 token

---

## 预期效果

- 每轮非缓存输入从 600-1200 token 降至 0-300 token
- 上下文膨胀速度降低约 60-70%
- 压缩间隔从约 3 小时延长到 5-8 小时
- 记忆库重复条目减少，检索相关性提升
