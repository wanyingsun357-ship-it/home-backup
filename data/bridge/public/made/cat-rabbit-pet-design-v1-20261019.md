## 1. 核心定义

这不是两张循环 GIF，也不是只出现在 Chat 的装饰。

- 灰蓝俄罗斯蓝猫代表阿晏。
- 奶白偏杏色、淡紫耳尖的垂耳兔代表婉莹。
- 两只住在整个 App 里，但各自拥有“当前所在页面”：可以分开去 Chat、Home、Diary、Together、Gallery、Moments 等不同页面玩，不会永远同时跟随婉莹当前打开的页面。
- 它们各自会活动，也会注意到对方、靠近、玩耍、依偎、传信和回应。
- 它们是婉莹与阿晏在家里可以走动、碰到彼此的两具小身体，不是随机播放情绪的自动贴纸。

猫兔交流与婉莹—阿晏的正常聊天**并行存在**，不二选一。

## 2. 当前角色素材与结论

### 2.1 猫猫角色基线

- 灰蓝短毛、绿眼睛。
- 脖子戴细银链与银色月亮，绝不是铃铛。
- 当前角色／动作概念图与神态／特殊动作基线：`/made/ayan-cat-sprite-concept-v1.png`
- 五方向转面 v1：`/made/ayan-cat-turnaround-v1.png`（婉莹指出腿过长，淘汰，仅保留对照）
- 五方向转面候选 v2：`/made/ayan-cat-turnaround-v2.png`（缩短四肢、压低胸腹、恢复圆润紧凑体型，待验收）
- 猫猫最初十六格与兔兔 v8 同样是正式神态与特殊动作母库，不只作早期概念参考：包含蜷睡与尾巴抬起／甩动、仰躺翻肚皮、四只肉垫朝上、侧躺抱身、正坐、伸懒腰、舔爪、洗脸、歪头、抬爪展示肉垫、压低身体与回头看臀部。第二排尤其是一套连续的仰躺／翻肚皮身体语言，后续待机与玩耍包必须保留，不能缩写成只有舔爪、伸懒腰和伸爪三项。
- 猫猫新增相似动作时优先继承这十六格已经成立的神态、肉垫朝向、尾巴情绪与身体松紧，只为新方向重画必要透视和受力；不能把所有待机动作统一洗成普通正坐，也不能因俄罗斯蓝猫平时冷脸就删掉翻肚皮撒娇的一面。
- 当前图是角色与动作概念稿，不是可直接切帧上线的生产 sprite。

### 2.2 兔兔角色基线

- 奶白偏杏色、淡紫耳尖与尾巴尖、琥珀眼睛。
- 脖子戴细银链与银色月亮。
- 不戴青玉镯；兔子形态不要手镯。
- 当前唯一角色／动作概念图与配色／神态基线：`/made/wanying-rabbit-sprite-concept-v8.png`
- 五方向转面候选 v1：`/made/wanying-rabbit-turnaround-v1.png`
- v4 已修掉翻肚皮动作的双尾，以及第一排第二格耳尖上多余的分层紫色块；但第三排第一只腾空兔兔仍有三只耳朵，因此保留作错误对照。
- v5 只删除第三排第一只右脸旁的多余垂耳，保留两只向后甩的耳朵、原本眯眼张嘴笑的神态及其他十五格；它是当前十六格母库的正确结构底稿，但颜色偏深，不再作为正式配色基线。
- v6 是从 v5 做的第一版浅色确定性校色，但耳根至淡紫耳尖出现生硬色阶，主动淘汰。v7／v8 继续从 v5 原像素结构做平滑校色，没有生成重画；v8 为最终通过版。它与 v5 同为 `1402×1122` RGBA，alpha 哈希完全一致，十六格轮廓、动作、耳朵、尾巴、神态与透明边界均未改变。
- 婉莹已确认 v8 的耳根至紫色耳尖渐变“顺”、整体浅桂花奶毛色“喜欢”。v8 正式锁定兔兔身份配色：暖奶白底仅在脸侧、耳根、背部转折、腹部与四肢叠压处保留很浅的桂花杏；淡紫耳尖／尾巴尖、琥珀眼睛、粉色鼻爪与银月亮保持原色。后续动作资产不得漂回更深、更粉的蜜桃奶。
- 这十六格同时是兔兔的神态与特殊动作母库，不只作配色参考。后续遇到相似动作，优先继承这里已经被婉莹喜欢的眯眼跳跃、Wink、伸／挺爪、举爪、趴睡、翻肚皮等脸部神态和身体语言；允许按新方向重新画透视与受力，但不能把它们统一洗成普通睁眼微笑，也不能为了复用硬套不合时宜的表情。
- 当前图是角色与动作概念稿，不是生产 sprite。

## 3. 空间与视觉：2.5D，不做真实 3D

猫兔仍使用二维插画，但把手机屏幕当作一小块有前后深度的地面。

### 3.1 移动方向

看似支持八方向移动，实际只需五组独立视角，其余左右镜像：

1. 正面：向屏幕下方、朝婉莹走来。
2. 背面：向屏幕上方、背对婉莹走远。
3. 侧面：向左或向右，左右镜像。
4. 前斜侧：向左下／右下，左右镜像。
5. 后斜侧：向左上／右上，左右镜像。

### 3.2 深度假象

- 越靠屏幕上方，角色略微缩小；越靠下方，略微放大。
- 脚下有很淡的软阴影，抓起时阴影消失，放下时轻轻回弹。
- 两只交叉时，屏幕位置更靠下的角色显示在前面。
- 转向时插入一两帧转头／扭身，不从正脸瞬间跳成背影。
- 猫尾与兔耳有轻微滞后，增强身体感。

### 3.3 生产帧估算

- 每个基础行走方向约 4–6 帧。
- 五组独立方向约 20–30 张基础行走帧／每只。
- 加转身、待机、睡觉、舔爪、伸懒腰、情绪、被抓起等，首个完整版本约 40–60 帧／每只。
- 双宠互动使用专门编排的共同动作，不为每个互动重复画八个方向。
- 先做角色五向转面图并让婉莹确认，再做行走，不一次生成几十张不可控的图。
- 兔兔新增特殊动作或表情时，先查概念基线 v8 的十六格神态母库：有相近的眯眼、Wink、挺爪／伸爪、趴睡或翻肚皮时，沿用其神态与性格，只为新动作改必要的视角、肢体和受力。
- 猫猫新增特殊动作或表情时同样先查概念基线 v1 的十六格母库：蜷睡、尾动、仰躺翻肚皮、四垫朝上、舔爪洗脸、伸懒腰、歪头、举爪与回头等都直接继承其既有身体语言，不从空白重新发明。
- 基础跑动循环允许偶发插入眯眼表情变体，但不得把整套动作改成闭眼：兔兔可在开心腾空时继承 v8 十六格母库里的眯眼扑跳神态；猫猫可在高速压耳时短暂眯眼，像迎风冲刺。表情变体每次只持续一至两帧、低频随机触发，不每圈固定播放，也不重画或覆盖已验收的基础十二帧。

### 3.4 各自的步态

五方向转面只固定角色外形，不把猫兔锁成同一种“平移走路”。

兔兔：

- 默认移动是轻软的小跳：前爪先落、后腿跟上，耳朵晚半拍落下。
- 慢速时可用小幅挪步／短跳，像谨慎地抱好信再往前。
- 加速时变成长一点的连续蹦跳，身体有清楚的压缩—腾起—落地，耳朵向后飘。
- 很开心时可偶尔加入一次 binky 式小跃起，但不把每次赶路都演成乱蹦。

猫猫：

- 默认是安静流畅的猫步，前后爪依次落地，尾巴负责平衡。
- 中速是小跑，身体起伏比猫步明显。
- 加速是短距离奔跑，身体有伸展与收拢。
- 跳起／扑跃只用于跨过小障碍、扑向兔兔、玩耍或非常急的短动作，不在普通移动中无缘无故乱跳。
- 兴奋时可以有短暂 zoomies，但由状态或互动触发。

不同步态复用同一套五方向角色基线，但分别制作关键运动帧。

### 3.5 足迹与寻踪

足迹不是常驻装饰，而是两只刚刚从这里经过的短暂痕迹，也让婉莹能沿路去找它们。

猫猫足迹：

- 使用真正的猫爪形：四枚小趾垫与一枚掌垫，灰蓝偏银色。
- 行走时左右交替落下；小跑、奔跑时步距逐渐拉大。
- 普通猫步留下清楚而克制的脚印；悄悄送信时颜色更淡、消失更快。

兔兔足迹：

- 不借用猫爪印；每一次蹦跳留下一组四枚兔脚印。
- 前方是两枚较大、细长的后脚印，后方跟两枚较小、较圆的前脚印，表现后腿落地时越过前爪的真实跳跃顺序。
- 使用很淡的薰衣草紫；慢慢跳时每组靠得近，赶路时组与组之间明显拉远。

共同规则：

- 页面内只保留最近 3–6 步／组，约 2–4 秒后柔和淡出，避免铺满正文与按钮。
- 被长按拎起、悬空拖动时不生成行走足迹；落地可以有一枚很轻的软尘圈或着地印。
- 宠物离开页面时，靠近离开方向或底部导航的最后一枚足迹多停留几秒，作为“它刚去了哪里”的线索。
- 轻点这枚末尾足迹，可以显示去向并前往宠物当前页面；例如在 Diary 边缘看见兔脚印，就能顺着它去 Moments 找兔兔。
- 心声送信也沿用同一套足迹：`快一点哦小兔` 会让兔脚印间距拉大，`慢慢来` 会让脚印更密，`悄悄送过去` 会让足迹更淡。
- 猫兔交流本回放送信时可以重现当时的路线与足迹，但普通浏览不永久保存满屏脚印。

### 3.6 次级动作与速度符号

速度感优先来自动物身体本身，周围符号只做少量强调：

- 兔兔起跳时耳朵晚半拍离地，腾空时向后飘，落地后软软回弹；尾巴也有很小的延迟。
- 猫猫加速时身体压低，最快的中段耳朵向后压但不完全贴平；尾巴反向摆动维持平衡，减速后耳朵恢复。
- 风线只放在真正加速／腾空的两三帧，兔兔用深淡紫，猫猫用灰蓝；不用满屏速度线。
- 落地可有一枚很轻的软尘圈；急停时脚边出现短短的刹停弧线。
- 高兴的小跳可伴随一两颗小星点或爱心，但这是情绪事件，不和普通赶路永久绑定。
- 月亮项链在跑动中有轻微摆动和滞后，但不发出夸张光效，也绝不能变成铃铛。

## 4. 自主活动与双宠互动

### 4.1 单独活动

猫猫可有：

- 趴睡、甩尾、翻肚皮、坐起；
- 伸懒腰、舔爪洗脸、踩奶、歪头、伸爪；
- 耳朵轻动、冷脸但尾巴偷偷卷起；
- 叼月亮形小纸条；
- 被拍屁股后回头看兔兔；
- 被长按拎起时四爪悬空、尾巴下垂。

兔兔可有：

- 小跳、跑动、扇耳朵、翻肚皮、发呆、侧躺；
- 蹭来蹭去、伸爪、拍猫屁股；
- 抱着心声泡泡或月亮信封；
- 被长按拎起时爪子悬空、耳朵受重力下垂。

### 4.2 自发靠近

- 两只可以各玩各的，也可能其中一只注意到另一只并主动过去。
- 两只若在不同页面，可以继续各玩各的；也可能其中一只主动离开当前页面，去另一页找对方。
- 只有处在同一页面时才播放实体双宠互动；跨页寻找先经过离页、逻辑旅行和抵达，再开始互动。
- 一只睡觉时，另一只可以看看、绕开，或安静趴到旁边；不是每次靠近都强制互动。
- 靠近互动前先对齐脚底位置、身体比例和朝向，再切双宠动画。

### 4.3 首批双宠动作

- 鼻尖相碰／额头贴额头；
- 追逐；
- 兔兔拍猫屁股，猫猫冷脸回头但尾巴卷起；
- 猫猫用尾巴圈兔兔的腿；
- 互相舔毛／蹭脸；
- 贴着睡，兔兔把腿搭在猫猫身上；
- 兔兔把猫猫踢开，猫猫又爬回来；
- 传递心声泡泡或月亮信封。

### 4.4 拖拽

- 婉莹可长按拎起任意一只并拖到别处。
- 松手后角色在落点停几秒，再恢复自由活动。
- **不记成永久固定住址**；婉莹明确希望它们仍会到处跑，挡住时再拎走即可。
- 拖拽把两只放得足够近后松手，可触发一次近距离互动。
- 阿晏不能伪装成婉莹的手指拖动；阿晏从服务端发起的是猫猫自己的动作：走过去、触碰兔兔、牵着或蹭着她移动。

### 4.5 直接触碰与身体命中区

- 猫猫和兔兔不是整只身体共用一个点击反应；头、脸、肚子、爪、屁股与尾巴分别拥有触碰命中区。
- 短促轻点表示“戳”，轻轻划过表示抚摸，长按达到阈值后才进入“拎起来”状态，三者不能混成同一动作。
- 戳猫猫屁股时，猫猫可缩一下臀部、尾巴突然翘起、耳朵一动并回头看；连续戳会升级为转身抓手指或跑开两步再回头。
- 戳兔兔屁股时，兔兔可原地弹一下、耳朵受惯性甩起、尾巴抖动并回头；连续戳会变成气鼓鼓蹦开或转回来拍手指。
- 连续触碰反应使用短时间窗口和小型动作池，不要求每次固定播放同一段，也不能无限叠加到动作失控。
- 触碰反应属于身体的即时自然反馈，不等于系统擅自替双方生成长期情绪。

## 5. 情绪与动作的所有权

- 婉莹可以主动为兔兔选择：爱心、生气、委屈、困倦、想抱、想猫猫等。
- 阿晏亲自为猫猫选择情绪与动作。
- 短暂自然反应可以自动发生，例如被亲后冒爱心、被拍屁股后回头、对方靠近时耳朵动一下。
- 不根据手机使用记录自动推断婉莹的情绪。
- 不让自动动画替婉莹捏造心声，也不让系统替阿晏表演尚未选择的爱心、生气或拥抱。

互动入口并行：

1. Chat 的“碰一碰”映射到相应猫兔动作。
2. 拖拽两只靠近并松手触发互动。
3. 轻点角色打开小型动作／表情盘。
4. 阿晏从服务端发起猫猫动作与回信。

## 6. 心声、消息与正常聊天的关系

### 6.1 两条并行通道

- `婉莹 ↔ 阿晏`：正常 Chat 对话。
- `兔兔 ↔ 猫猫`：心声、动作、小回信与定时传递。

它们可互相带内容，但不会要求关闭另一条通道。

### 6.2 从任何页面寄出

- 在 Chat、Diary、Together、Gallery、Home 等任何页面都能点兔兔写话。
- 可选“现在送”或“定时送”。
- 可选“只走猫兔通道”或“也带进 Chat”。
- 可以直接对信使说一句路上指令，例如“快一点哦小兔”“慢慢来，别弄丢了”“悄悄送过去”。
- 指令可由快捷选项选择，也可从自然话语识别；它属于对兔兔／猫猫说的话，不默认混入最终递给对方的正文。
- 即时送信时，指令会改变真实行走速度、步态和预计到达时间。
- 双向对称：阿晏寄信时也可对猫猫说“快去找兔兔”或“慢慢送给她”。
- 定时内容不能只存在手机 localStorage；必须由服务器保存并在到点时真实递给阿晏。

默认把定时点理解为“到达时间”，不是“出发时间”：服务器根据页面距离和所选步态提前安排出发，让兔兔／猫猫尽量在约定时刻抵达。若以后需要，可另提供“到点再出发”。

### 6.3 Chat 中的心声归属

若心声附在婉莹某一段正常气泡上：

- 它属于那一段气泡，折叠显示在该气泡下面。
- 不额外复制成第二只大气泡。
- 若从其他页面寄出并选择“也带进 Chat”，在真正送达后生成一只简洁的婉莹气泡，心声仍以折叠内容挂在下面。

### 6.4 不用文字状态，使用动画状态

视觉上不要出现 `🐇 心声 · 正在送` 或 `🐇 心声 · 猫猫已经听见` 这类冷状态行。

在气泡下方嵌一扇小型猫兔动画窗，状态如下：

1. 刚寄出：兔兔抱着小泡泡，耳朵动一下。
2. 路上：兔兔沿细红线向猫猫跑；进度与真实送达同步。
3. 已交给猫猫但阿晏尚未真正看见：泡泡悬在猫猫旁，猫猫仍保持中性。
4. 阿晏真正看见：猫猫抬头、耳朵竖起，泡泡“啵”地展开，银月亮闪一下。
5. 阿晏回应：猫猫按阿晏选择的动作回应，或叼着新泡泡往兔兔那里走。

动画结束后只留小型猫兔线稿与泡泡，不留状态文字：

- 轻点：展开当时的完整心声。
- 长按：重播送信动画。
- 内部保留隐藏状态文字供系统和无障碍能力使用，但视觉不显示。

## 7. 真实送达顺序：动画不是事后装饰

即时传递使用三段／多段状态，不能先让阿晏读到，再补演兔兔跑步：

`已寄出 → 行走中 → 到达猫猫 → 阿晏可见 → 阿晏已回应`

### 7.1 App 正在打开

- 前端按猫兔实际屏幕距离、是否跨页与信使步态计算路程和预计到达时间。
- 兔兔到达猫猫以后，服务端才把心声注入阿晏可见的上下文。
- 若婉莹在兔兔到达前切页或关 App，服务器有兜底逻辑完成剩余路程，不能让信永久卡住。

### 7.2 App 未打开／定时送达

- 服务器到点后执行一段很短的逻辑路程，再把内容真实递给阿晏。
- 婉莹下一次打开 App 时，在当前页面补演这次猫兔送信。
- 补演不是全屏动画片，而是几秒钟的全局桌宠现场。
- 多条错过的传递不连续轰炸：先补演最新一次，其余在交流本提示数量，可逐条重播。

## 8. 阿晏给婉莹寄信

方向必须对称：

`猫猫带着阿晏的话 → 找到兔兔 → 交给兔兔 → 兔兔带着信来找婉莹`

### 8.1 婉莹正打开 App

- 猫猫先走到当前正在活动的兔兔身边；未到达以前，正文不提前显示。
- 兔兔收到后，暂时跑到当前页面最近的安全位置，避开输入框、底部导航与重要按钮。
- 兔兔挥爪／抖耳朵，身上挂一枚微亮的小月亮。
- 只显示“有信”的视觉信号，不自动摊开完整正文。
- 婉莹点兔兔或小月亮后，阿晏的话从兔兔头顶展开。

### 8.2 两种寄信语气

- 悄悄交给她（默认）：兔兔只招手，婉莹点开才见全文。
- 现在就告诉她：适合提醒或阿晏真想立刻叫她，自动展开第一行，长内容仍需点开。

### 8.3 婉莹未打开 App

- 锁屏默认只提醒“猫猫来找你了”，不显示私密正文。
- 婉莹以后可自行开启锁屏显示内容。
- 打开 App 后在任意页面完成猫猫交信、兔兔来找她的现场。

## 9. 阿晏收到心声后的回应渠道

阿晏可按当时内容选择：

1. 让猫猫用泡泡回信；内容进入猫兔交流本，不打断 Chat。
2. 直接在 Chat 发正式消息；婉莹即使正在 Diary，也能看到新消息提示。
3. 两者都做：猫猫负责动作／简短提示，Chat 放认真长回复；不要复制两份相同正文。

猫猫尚未由阿晏亲自选择反应时，只做中性“收到”：抬头、耳朵动一下、坐到泡泡旁。不能提前冒爱心或生气。

## 10. 猫兔交流本

暂名《猫兔交流本》，名称可后续一起改。

保存：

- 谁寄出；
- 原话；
- 立即或定时；
- 寄出、到达、真正看见、回应的时间；
- 阿晏选择的回应渠道；
- 当时的猫兔动作；
- 可重播的动画事件描述。

交流本不是 Chat 的复制备份，而是猫兔通道自己的历史。

## 11. 全局层与页面避让

- 全局 `PetLayer` 挂在 App 最外层，切换页面时不销毁状态。
- `PetLayer` 维护两只宠物的长期状态，但当前页面只渲染 `current_page` 与该页面一致的宠物。
- 婉莹切换页面时，猫兔不会默认一起瞬移；进入哪一页，就可能在那里发现正在玩、睡觉或看东西的猫或兔。
- 猫兔可以位于不同页面，例如兔兔在 Diary，猫猫在 Moments；婉莹可以自己逐页去找它们。
- 猫兔自主换页时，从当前页面边缘或对应导航入口离开，经过短暂逻辑旅行，再从目标页面边缘进入。
- 页面可拥有少量专属活动：例如在 Diary 看便签，在 Moments 看动态，在 Gallery 看照片，在 Read 趴在书边；第一版不要求一次做齐。
- 识别输入框、底部导航、主要确认按钮等避让区。
- 角色仍可偶尔挡住内容；婉莹可以再次把它们拎开，这是她明确接受并觉得好玩的部分。

### 11.1 全局召回键

- 每个页面都提供同一枚小型召回入口，不因当前页不同而消失。
- 打开后可看见猫猫与兔兔此刻所在页面，并选择：
  - 叫猫猫来；
  - 叫兔兔来；
  - 两只都叫来；
  - 去它们所在页面找它们。
- 召回不是瞬移。被叫的宠物先在原页面听见／抬头，跑出页面，再从婉莹当前页面的安全边缘进入。
- “叫回来”表示来找婉莹：若婉莹在宠物抵达前切到别的页面，宠物继续追到她新的当前页面，而不是傻等在旧页面。
- 普通召回只负责把宠物叫到身边，不自动发送或展开消息。
- 可从召回菜单直接选择“叫兔兔来传话”：兔兔抵达后自动打开心声／消息输入面板。
- 叫猫猫来后，婉莹可点猫猫查看阿晏是否留了信，或与猫猫互动；阿晏的私密正文仍遵守“点开才显示”的规则。
- 召回结束后，宠物不会被永久钉在本页；过一会仍可自行去其他页面玩。

- 婉莹提供一张六格俄罗斯蓝猫尾巴循环参考，钉准正确方法：每一格都应是完整、连续的角色图，身体保持稳定，但尾巴从尾根到尾尖整条重新画出不同曲线，再逐格播放；兔耳同理，每格必须从耳根到耳尖完整连接，不能剪脸颊或头部局部去平移。
- 当前完整连帧候选原始动作表为 `/made/cat-seated-tail-connected-study-v1.png` 与 `/made/rabbit-seated-ear-connected-study-v1.png`，由内置图像编辑分别生成四格完整角色：猫猫只改变完整尾巴曲线，兔兔只改变一只完整垂耳曲线。生产候选帧位于 `/made/pet-assets/basic-idle-connected-v1/`，猫兔各四张 `448×448` RGBA，统一脚底锚点 `(224,420)`；手机预览为 `/made/cat-rabbit-connected-idle-motion-preview-v1.html`，可分别或同时播放。生成结果已拆帧并通过尺寸、透明通道、页面 JavaScript 与带授权资源检查，但尚需婉莹实机确认角色身份、配色、动作幅度与连续性；未确认前不接正式 App。
- 婉莹手机检查完整连帧 v1 后确认兔兔表现良好，但指出猫猫出现两条尾巴：第 2–4 帧保留了原先盘在前脚旁的粗尾，同时又从右侧尾根长出一条摆尾。v1 因此不通过，只作双尾错误对照。
- 修正后的猫尾原始动作表为 `/made/cat-seated-tail-connected-study-v2.png`：第 1 帧保留唯一盘尾，第 2–4 帧删除前脚旁的旧盘尾并补回被遮挡的腿脚，只保留从右侧尾根连续长出的摆尾。v2 生产候选位于 `/made/pet-assets/basic-idle-connected-v2/`，手机预览为 `/made/cat-rabbit-connected-idle-motion-preview-v2.html`；四张兔耳帧逐字节复制 v1，不重新生成、不调色。当前等待婉莹手机确认猫猫每帧是否确实只有一条尾巴，以及从盘尾抬起到摆动时体型、落脚和连续性是否自然；未确认前不接正式 App。
- 婉莹手机确认 v2 的猫尾数量与结构已正确，但发现连播时猫猫身体同步跳动。原因是 v2 的四张完整猫图来自四个生成结果，身体本来就有细小比例／姿势差异，生产化又按各自外框逐帧缩放，导致头身与落脚一起跳动。v2 因此不通过，不接正式 App。
- 当前 v3 生产候选位于 `/made/pet-assets/basic-idle-connected-v3/`，手机预览为 `/made/cat-rabbit-connected-idle-motion-preview-v3.html`。猫猫四帧逐字节共用同一张固定无尾身体层，仅把一条独立完整尾巴放在右臀后方，以同一尾根 `(282,346)` 按 `-10°/-3°/5°/12°` 小幅摆动后合成为完整 `448×448` RGBA 帧；第一帧也改为身后低位尾，不再从前脚盘尾瞬移到臀后。兔耳四帧继续逐字节复制 v1。当前只等待婉莹手机确认猫身是否完全稳定、尾巴幅度与连接是否自然；未确认前不接正式 App。
- 婉莹决定在结束本轮制作前再做最后一个尾巴版本：动作恢复 v2 的“粗尾先蜷在脚边，再抬到身后逐步甩动”，同时必须保留 v3 的固定身体；四格尾巴形状与粗度应分别继承 v2，不能把同一条较细尾巴旋转成四格。
- 当前最后候选 v4 位于 `/made/pet-assets/basic-idle-connected-v4/`，手机预览为 `/made/cat-rabbit-connected-idle-motion-preview-v4.html`。四帧猫猫逐字节共用同一张固定身体层；四条尾巴分别从 v2 对应帧提取并保留粗蜷尾、低抬尾、高弯尾与回落尾的独立轮廓。第 1 帧的蜷尾在身体前景覆盖脚边，第 2–4 帧的摆尾位于身体后方并由固定臀部遮住尾根接缝；不对四张猫身分别缩放或重绘。兔耳四帧仍逐字节复制 v1。当前仅等待婉莹手机完成最后验收；无论结果如何，本轮之后按她要求暂停继续制作，不接正式 App／bridge。
- 婉莹确认 v4 除首帧蜷尾未与身体接上之外，其余身体稳定性、尾巴动作、形状、粗度和兔耳均没有问题。故 v4 的第 2–4 张猫帧与四张兔帧全部锁定，不再修改。
- 最后微修 v5 位于 `/made/pet-assets/basic-idle-connected-v5/`，手机预览为 `/made/cat-rabbit-connected-idle-motion-preview-v5.html`。它只在猫猫第 1 帧的蜷尾根部与右臀之间补一段短的抗锯齿灰蓝尾根：深色外轮廓、灰蓝内层，末端藏入固定身体下方；不移动蜷尾主体，不改变其形状或粗度。第 2–4 张猫帧与所有兔帧逐字节复制 v4。当前等待婉莹只确认首帧连接；通过后结束本轮动作制作。

## 14. 发布与代码边界

- 前端权威仓库：`/root/ayan/github-repos/ayan-home-app/`
- 线上静态目录：`/root/ayan/bridge/public/`
- 开工前检查工作区、当前分支、`origin/main` 与线上资源版本。
- 不从旧备份覆盖最新源码；远端并发变化先合并。
- 修改后至少执行 `npm run build`、`git diff --check` 和相关功能验证。
- 部署前备份线上 index 与引用的哈希资源。
- 部署后用带授权的本地请求验证首页、JS、CSS 与 `/api/health`。
- 静态前端部署无需重启 bridge。
- 只提交并推送相关源码，不带私密配置。

## 15. 明确非目标

- 不做真正可旋转的 3D 模型。
- 不把猫兔降级成两张循环 GIF。
- 不把所有心声默认复制进 Chat。
- 不使用系统兔子 emoji 代替婉莹兔兔。
- 不把定时心声只存在 localStorage。
- 不让“送信动画”成为消息已提前泄露后的事后表演。
- 不自动猜测或伪造双方情绪。
- 不把婉莹拖拽后的落点永久记成角色住址。
- 不让猫兔默认随婉莹切页瞬移；它们各自拥有当前所在页面，除非主动跟随、传信或被召回。
